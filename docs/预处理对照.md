# 预处理对照 A/B

在同一进程、同一张 1080p RGB 图上对比：

| 路径 | 做法 |
| --- | --- |
| **A** | CPU 双线性 letterbox → `memcpy` 进 `rknn_create_mem` 的虚拟地址 |
| **B** | `rknn_create_mem` 拿到 **dma-buf fd**，RGA `improcess` 直接写入该 fd（`rknn_set_io_mem` 只在初始化绑一次） |

## 实测（200 次，Orange Pi 5 / RK3588S）

| | preprocess P50 | preprocess P99 |
| --- | ---: | ---: |
| A CPU letterbox + memcpy | **25.5 ms** | 26.0 ms |
| B RGA → rknn fd | **5.3 ms** | 9.4 ms |
| 加速比（P50） | **4.8×** | |

摘要：[`bench/logs/preprocess_ab_summary.json`](../bench/logs/preprocess_ab_summary.json)。  
B 路径最后一帧 `cls_max≈0.87`，说明写入的 buffer 能被 NPU 正确推理。

## 板上复现

```bash
# 需要 third_party/librga 与 rknn_api.h（见 scripts/fetch_third_party.sh）
scp -r cpp third_party yolov8n_int8.rknn root@板子IP:~/ab_bench/
# 板上
cd ~/ab_bench
./cpp/build_ab_bench.sh
python3 -c "import cv2; import numpy as np; \
  i=cv2.cvtColor(cv2.imread('bus.jpg'),cv2.COLOR_BGR2RGB); \
  cv2.resize(i,(1920,1080)).tofile('frame_1080p.rgb')"
./cpp/preprocess_ab_bench yolov8n_int8.rknn frame_1080p.rgb 1920 1080 200
```

## 口径与边界

- 记的是**服务时间**，不含排队。
- A 使用便携双线性实现（与 OpenCV SIMD 不是同一实现）。OpenCV letterbox 在 cache 热时微基准约 5–6 ms，可作参考，**主表以同进程 A/B 为准**。
- 当前输入已是 RGB。后续接 MPP 的 NV12 时，B 还可把 **CSC + letterbox** 合成一次 RGA，相对「软解 + cvtColor + letterbox + memcpy」的优势会更大。
- 简历里的 A/B 只填上表 P50；指得到本 JSON 再写。
