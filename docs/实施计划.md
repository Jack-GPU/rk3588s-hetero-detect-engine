# RK3588S 四路视频结构化实施计划

简历项目的主线是端侧系统，不是从零训一个检测器。板子已经到位，从板端环境开始；训练在 PC 上和点亮并行，用 COCO 预训练的 YOLOv8n 做域微调。

## 验收线

| 指标 | 目标 |
| --- | --- |
| 吞吐 | 单芯片 4 路 1080p 实时检测与结构化输出 |
| 延迟 | 端到端 P99 ≤ 120 ms |
| CPU | 8 核平均占用 ≤ 45% |
| 功耗 | 整板 ≤ 10 W |
| 稳定 | 连续运行 2 小时不降频 |

技术栈：RK3588S（4×A76 + 4×A55，Mali-G610，6 TOPS 三核 NPU）、RKNN Runtime、MPP、RGA、DMA-BUF、DRM/KMS、YOLOv8n、C++17 / Python。

## 今天就做

板端环境先跑通。权重可以后换。PC 上的 RKNN Toolkit2 和板子上的 RKNN Runtime 版本必须成对，否则后面所有模型都会在部署时失败。

1. 记下板卡厂商镜像、内核版本、`/proc/device-tree` 里的 `compatible`，确认是 RK3588S。
2. `dmesg` 里看到 `rknpu`，`rknn_server` / `librknnrt` 能加载，三核可用。
3. 跑通 Rockchip 官方 YOLOv8 + MPP 单路 demo，1080p 能出框。先不管帧率和功耗。
4. 在 PC 上锁定与板端 runtime 匹配的 rknn-toolkit2，同一版本文档能把 ONNX 转成 `.rknn` 并在板上跑。
5. 用 COCO 预训练 `yolov8n.pt` 走**混合 INT8**（见 `python/convert_rknn.py`）作为精度和速度基线。全 INT8 会把类别分数压成 0。

## 训练做到哪一步就停

结构化输出先是检测框加上类别：人、车、非机动车。跟踪、属性、ReID 等四路延迟达标后再加。

| 选择 | 做法 | 什么时候用 |
| --- | --- | --- |
| 预训练直出 | yolov8n COCO 权重，只做 RKNN 量化 | 域和 COCO 接近，mAP 已经够讲 |
| 域微调 | 冻结 backbone 前几层，在 VisDrone 或自采 2k–5k 张上训 50–100 epoch | 场景是路口、园区、无人机俯视 |
| 换结构 | 把 SiLU、部分 Slice、非对称 pad 换成 RKNN 有映射的等价算子后再微调几个 epoch | 逐层 profile 出现 CPU fallback |

PC 上的流水线：

1. **数据。** 优先公开集。VisDrone 适合小目标路口；通用监控用 COCO 里 person / car / bus / truck / motorcycle / bicycle 抽成三类。自采数据只做补充，先标 500 张看 loss，再扩到几千张。
2. **训练。** Ultralytics YOLOv8n，输入 640。`imgsz`、mosaic、letterbox 必须和板上 RGA 的缩放对齐，否则量化后框会漂。
3. **导出。** `best.pt` → ONNX（固定 batch=1，opset 以 toolkit 文档为准）→ rknn-toolkit2 做 INT8 per-channel。校准集 200–500 张，从验证集按场景抽样，不用训练集增强图。
4. **验收。** 板上 INT8 相对 PC FP32，mAP50 掉点控制在 2 以内。掉得多先查校准集和 letterbox，再查 fallback 算子，再考虑加 epoch。

## 板端主线

**全链路零拷贝（阶段 4）。** MPP 硬解出 DMA-BUF，RGA 做缩放和色域转换，RKNN 用 `rknn_create_mem_from_fd` 直接吃这块 buffer，DRM 显示同一条 fd。CPU 不碰像素。先做通一路，再扩到四路。

**三核调度（阶段 5）。** 4 路流对 3 个 NPU 核。对比单核串行、静态绑核、`NPU_CORE_AUTO`。`NPU_CORE_AUTO` 会把 P99 抖上去。最终用按分辨率静态绑定，空闲核再接管。

**流水线与功耗（阶段 6）。** 解码、预处理、推理、后处理、输出五段线程，有界队列和乒乓缓冲。单线程 NMS 和 RGA/NPU 抢 DDR 要单独记延迟。功耗用频率-功率曲线锁 DVFS。延迟用本地固定码率文件测。

## 每阶段要留下的数字

阶段 1 结束时填上基线列。

| 指标 | 阶段 1 基线 | 阶段 6 目标 | 怎么测 |
| --- | --- | --- | --- |
| 路数 × 分辨率 | 1×1080p 软/硬已测；**4×1080p30 队列已测** | 4 × 1080p | 限速文件模拟实时 |
| 端到端 P99 | 单路硬解 28.5 ms；四路 AUTO **69.5 ms**（含排队，无 NMS） | ≤ 120 ms | `mpp_multi_queue_summary.json` |
| 四路吞吐 / 丢帧 | AUTO **T≈55 fps / drop≈27%**（需求 120） | 尽量抬 T、控丢帧 | 同上 |
| NPU 单帧 | 软解 P50 35.6；硬解单路 infer P50 **25.6 ms** | 按负载反推 | 阶段 4 / 队列摘要 |
| 8 核平均 CPU | **~14.6%**（短窗 mpstat） | ≤ 45% | 正式测再拉长到 10 分钟 |
| 整板功耗 | 待测 | ≤ 10 W | USB 功率计或板载 INA，含解码和显示 |
| INT8 mAP50 掉点 | 待测 | ≤ 2 pt vs FP32 | 同一验证集，PC FP32 对板端 INT8 |
| 热稳定 | 待测 | 2 h 不降频 | 记录 NPU/CPU 频率和温度曲线 |
