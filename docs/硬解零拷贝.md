# MPP → RGA → RKNN 硬解零拷贝（阶段 4 单路）

路径：`MPP H.264 硬解 → RGA NV12 letterbox(+CSC) → RKNN dma-buf fd → CPU NMS`。  
`rknn_set_io_mem` 只在初始化绑一次；像素路径走 dma-buf，NMS 在 CPU。

## 实测（120 帧，含 NMS，Orange Pi 5 / RK3588S）

| 段 | P50 | P99 |
| --- | ---: | ---: |
| decode | 0.37 ms | 0.94 ms |
| RGA preprocess | 2.01 ms | 2.31 ms |
| infer | 33.3 ms | 46.5 ms |
| post (NMS) | **2.78 ms** | 8.43 ms |
| e2e（含 NMS） | **31.4 ms** | **55.4 ms** |

摘要：[`bench/logs/mpp_rga_rknn_nms_summary.json`](../bench/logs/mpp_rga_rknn_nms_summary.json)。  
末帧 `dets=6`，`cls_max≈0.87`。不含 NMS 的旧表见 `mpp_rga_rknn_summary.json`（e2e P50/P99 27.8/28.5）。

## 板上复现

需要板上已有 `librknnrt` 2.3.2、`librga`，以及交叉编译得到的 `librockchip_mpp`（本仓库只入库 `third_party/mpp/include`；`librockchip_mpp` 需交叉编译或从板 SDK 获取）。

```bash
# PC：准备第三方头/库后，连同模型与码流拷到板
scp -r cpp third_party/mpp third_party/librga third_party/rknn \
  models/yolov8n_int8.rknn assets/bus_1080p30.h264 \
  root@板子IP:~/mpp_pipeline/

# 板上
cd ~/mpp_pipeline
bash cpp/build_mpp_pipeline.sh
./cpp/mpp_rga_rknn_bench yolov8n_int8.rknn bus_1080p30.h264 120
```

样例码流可由 mp4 抽出：`ffmpeg -i bus_1080p30.mp4 -c:v copy -bsf:v h264_mp4toannexb -an bus_1080p30.h264`。

## 边界

- 记的是**服务时间**，单路串行，不含排队与丢帧策略。
- 码流播完后 MPP 槽位清理可能打断言日志，不影响本表分位（已在 `max_empty` + `nanosleep` 后正常退出）。
- 尚未接 DRM 显示、四路 MPP 并发、有界队列与功耗长测。
