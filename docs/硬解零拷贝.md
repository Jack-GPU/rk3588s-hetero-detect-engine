# MPP → RGA → RKNN 硬解零拷贝（阶段 4 单路）

路径：`MPP H.264 硬解 → RGA NV12 letterbox(+CSC) → RKNN dma-buf fd`。  
`rknn_set_io_mem` 只在初始化绑一次；每帧 RGA 写入同一块 fd，CPU 不碰像素。

## 实测（120 帧，Orange Pi 5 / RK3588S）

| 段 | P50 | P99 |
| --- | ---: | ---: |
| decode | 0.34 ms | 0.36 ms |
| RGA preprocess | 1.86 ms | 1.90 ms |
| infer | 25.6 ms | 26.3 ms |
| e2e（上三段之和） | **27.8 ms** | **28.5 ms** |

摘要：[`bench/logs/mpp_rga_rknn_summary.json`](../bench/logs/mpp_rga_rknn_summary.json)。  
末帧 `cls_max≈0.86`，说明 NV12→RGB letterbox 写入的 buffer 可被 NPU 正确推理。

## 相对软解基线

软解基线（阶段 1）：`OpenCV 软解 → CPU letterbox → RKNN → CPU NMS`，见 [`单路基线.md`](单路基线.md)。

| | 软解 e2e | 硬解 e2e |
| --- | ---: | ---: |
| P50 | 61.1 ms | **27.8 ms** |
| P99 | 124.7 ms | **28.5 ms** |

口径差异（写简历时要说清）：

- 软解 e2e **含** CPU NMS（post P50 ≈ 5.5 ms）；硬解本表 e2e **不含** NMS。
- 去掉软解 post 后，decode+pre+infer 约 **55.6 ms**，相对硬解约 **2.0×**（P50）。
- 硬解 decode P50 **0.34 ms** vs 软解 **9.3 ms**；RGA 一次完成 CSC+letterbox。

## 板上复现

需要板上已有 `librknnrt` 2.3.2、`librga`，以及交叉编译得到的 `librockchip_mpp`（本仓库 `third_party/mpp/`，源码树 `third_party/mpp-src/` 不入库）。

```bash
# PC：准备第三方头/库后，连同模型与码流拷到板
scp -r cpp third_party/mpp third_party/librga third_party/rknn \
  models/yolov8n_int8.rknn assets/bus_1080p30.h264 \
  root@板子IP:~/mpp_pipeline/

# 板上
cd ~/mpp_pipeline
bash cpp/build_mpp_pipeline.sh
./cpp/mpp_rga_rknn_bench yolov8n_int8.rknn bus_1080p30.h264 120
```

样例码流可由 mp4 抽出：`ffmpeg -i bus_1080p30.mp4 -c:v copy -bsf:v h264_mp4toannexb -an bus_1080p30.h264`。

## 边界

- 记的是**服务时间**，单路串行，不含排队与丢帧策略。
- 码流播完后 MPP 槽位清理可能打断言日志，不影响本表分位（已在 `max_empty` + `nanosleep` 后正常退出）。
- 尚未接 DRM 显示、四路 MPP 并发、有界队列与功耗长测。
