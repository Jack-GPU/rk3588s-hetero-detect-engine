# 四路 MPP + 有界队列丢旧帧

路径：每路 `MPP H.264（30 fps 限速）→ 队列(depth=1, drop-old) → RGA → RKNN fd → CPU NMS`。  
与「只测 infer 的假四路」不同：含硬解、预处理、排队与 NMS。

## 实测（Orange Pi 5 / RK3588S，每路目标 60 帧）

输入：4 × 1080p @ **30 fps**（合计需求 **120** infer/s）。

不含 NMS 的对照见 [`mpp_multi_queue_summary.json`](../bench/logs/mpp_multi_queue_summary.json)。  
**含 NMS（AUTO）** 最新：

| 策略 | T_fps | 丢帧率 | post P50 | e2e P99 |
| --- | ---: | ---: | ---: | ---: |
| `NPU_CORE_AUTO` + NMS | **54.4** | **15.5%** | 2.75 ms | **72.7 ms** |

摘要：[`bench/logs/mpp_multi_queue_nms_auto.json`](../bench/logs/mpp_multi_queue_nms_auto.json)。

## 怎么读这些数

- **做不到 4×30 全开**：NPU 完成速率约 54 fps ≪ 120，必须靠丢帧保时效。
- **e2e 含排队 + NMS**：从入队到 NMS 结束；depth=1 丢旧帧，P99 约 **73 ms**。
- 不含 NMS 时 AUTO 相对静态更少丢、更低 P99（见旧表）；加 NMS 后主推 AUTO 数字。
- 简历可写：四路 1080p30 实时输入，AUTO + 丢旧帧 + NMS → **~54 fps**、丢帧 **~15%**、e2e P99 **~73 ms**。

## 板上复现

```bash
cd ~/mpp_pipeline
bash cpp/build_mpp_multi_queue.sh
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 auto 4 30
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 static 4 30
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 serial 4 30
```

## 边界

- 码流按 30 fps **限速送入**（模拟实时），不是离线尽速解码。
- RGA `improcess` 四路加了全局锁，避免驱动竞态；对 T 有少量串行化。
- 尚未接 CPU NMS / DRM；长测功耗与热稳定另测。
