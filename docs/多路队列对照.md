# 四路 MPP + 有界队列丢旧帧

路径：每路 `MPP H.264（30 fps 限速）→ 队列(depth=1, drop-old) → RGA → RKNN fd`。  
与「只测 infer 的假四路」不同：含硬解、预处理与排队。

## 实测（Orange Pi 5 / RK3588S，每路目标 60 帧）

输入：4 × 1080p @ **30 fps**（合计需求 **120** infer/s）。

| 策略 | T_fps | 丢帧率 | infer P99 | e2e P99 |
| --- | ---: | ---: | ---: | ---: |
| 单核争用 `CORE_0` | 46.2 | 68.3% | 94.1 ms | 128.2 ms |
| 静态绑核 0/1/2/0 | **56.5** | 32.6% | 48.3 ms | 78.1 ms |
| `NPU_CORE_AUTO` | 55.2 | **26.8%** | **40.8 ms** | **69.5 ms** |

摘要：[`bench/logs/mpp_multi_queue_summary.json`](../bench/logs/mpp_multi_queue_summary.json)。

## 怎么读这些数

- **做不到 4×30 全开**：NPU 完成速率约 55 fps ≪ 120，必须靠丢帧保时效。
- **AUTO 更适合「保 P99 + 少丢」**：相对静态，丢帧更低（26.8% vs 32.6%），e2e P99 更好（69.5 vs 78.1）。静态 T 略高，但流 0/3 共抢 `CORE_0`，这两路丢帧明显更多。
- **e2e 含排队**：从入队到 infer 结束；depth=1 时旧帧被挤掉，留下的帧排队不会无限涨。
- 简历可写：四路 1080p30 实时输入下，AUTO + 丢旧帧 → 合计 **~55 fps**、丢帧 **~27%**、e2e P99 **~70 ms**。

## 板上复现

```bash
cd ~/mpp_pipeline
bash cpp/build_mpp_multi_queue.sh
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 auto 4 30
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 static 4 30
./cpp/mpp_multi_queue_bench yolov8n_int8.rknn bus_1080p30.h264 60 serial 4 30
```

## 边界

- 码流按 30 fps **限速送入**（模拟实时），不是离线尽速解码。
- RGA `improcess` 四路加了全局锁，避免驱动竞态；对 T 有少量串行化。
- 尚未接 CPU NMS / DRM；长测功耗与热稳定另测。
