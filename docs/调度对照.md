# 三核调度对照

4 个并发 `RKNNLite` 上下文（模拟 4 路），同一 letterbox 后的输入，只计 `inference` 服务时间。

| 策略 | core mask | 推理 P50 | 推理 P99 | 合计吞吐 T |
| --- | --- | ---: | ---: | ---: |
| 单核争用 | 全 `CORE_0` | 89.1 ms | **114.7 ms** | 39.4 fps |
| 静态绑核 | 0/1/2/0 | 41.4 ms | **64.0 ms**（C） | **74.5 fps** |
| AUTO | 全 `AUTO` | 35.1 ms | **51.4 ms**（D） | **87.7 fps** |

样本：每路 120 帧，预热 15；总计量 480 次/策略。  
摘要：[`bench/logs/schedule_summary.json`](../bench/logs/schedule_summary.json)。

## 结论（按本次实测）

- 相对单核争用，静态绑核吞吐约 **1.9×**，P99 从 115 ms 降到 64 ms。
- 本组负载下 **AUTO 的 P99 与吞吐都优于静态绑核**（D < C，T_auto > T_static）。简历按实测写，不写「静态一定更好」。
- 静态绑核下流 0/3 同抢 core0，其 per-stream P99 高于独占 core1/2 的流——这是 4 路对 3 核的固有不均衡。

## 复现（板上）

```bash
python3 board_bench_schedule.py \
  --model yolov8n_int8.rknn \
  --image bus.jpg \
  --frames 120 \
  --warmup 15 \
  --out schedule_summary.json
```
